# 特能导 · 技术文档

> 版本 1.4.0 ｜ 技术栈：Electron 45 + Chromium 142 + Node 24
> 面向：后续开发者、维护者、二次开发者

---

## 一、技术选型

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 桌面框架 | **Electron** | 需要内嵌真实浏览器内核来完成登录、渲染、`printToPDF`；Tauri 的 WebView 抽象层无法满足多会话登录隔离与 CDP 调试能力 |
| 构建工具链 | **无（原生 HTML/CSS/JS + ES Module）** | 渲染层是单窗口多页面应用，引入 Vite/Webpack 只增加构建失败点，不增加收益；源码直接可读可改 |
| 打包 | **electron-builder + NSIS** | 一条命令产出中文向导的安装包，支持自定义安装目录、桌面快捷方式、卸载时询问是否删数据 |
| 正文识别 | **@mozilla/readability + 平台专用选择器** | Readability 处理通用站点，专用选择器保证公众号/知乎这类结构化站点的保真度 |
| HTML → Markdown | **turndown + turndown-plugin-gfm** | 支持表格、代码块等 GFM 扩展语法 |
| HTML → Word | **html-to-docx**（失败降级为 `.doc`） | 保留标题层级、表格与内嵌图片 |
| Word/PDF 保真思路 | **内联样式全量保留 + 阅读器样式兜底** | 公众号排版大量依赖 inline style，直接保留即可高度还原 |
| 持久化 | **JSON 文件（原子写入）** | 数据量小（历史记录、设置、规则），SQLite 属过度设计；原子写（写 `.tmp` 后 rename）避免崩溃损坏 |

**没有使用**任何需要本地编译的原生模块（如 better-sqlite3、sharp），确保 `npm install` 在任何机器上都能成功。

### 会话分区设计（关键）

统一使用 **`persist:tnd-capture`** 作为抓取分区：

- 内置浏览器（`<webview partition="persist:tnd-capture">`）
- 后台抓取窗口
- 图片下载（`session.fromPartition(CAPTURE_PARTITION)`）

三者**共用同一份 Cookie**。用户在内置浏览器登录一次，后台批量抓取与图片下载自动复用登录态。

## 四、核心流程

### 4.1 抓取流水线

```
submit(urls) → taskQueue 排队 → capture(url)
    │
    ├─ 1. createCaptureWindow()      创建屏幕外可见窗口
    ├─ 2. enableNetworkCapture()     CDP 注入网络钩子（失败降级，不影响主流程）
    ├─ 3. waitForLoad()              did-finish-load / did-fail-load / 超时
    ├─ 4. sleep(700)                 SPA 路由跳转静默期
    ├─ 5. runExtractionRetry()       executeJavaScript(拼接 Readability + 提取器)
    ├─ 6. deepCapture()              IMA 等：逐个点击目录项，合并多章节
    └─ 7. 销毁窗口，返回结果
```

**注入脚本的组成**（在页面主世界执行）：

```
executeJavaScript(`
  window.__TND_OPTS__ = {...}          // 选项
  <Readability.js 源码>                 // UMD，挂到 globalThis
  <extract-page.js 源码>                // 定义 window.__TND_EXTRACT__
  return await window.__TND_EXTRACT__() // 返回可 JSON 序列化的结果
`)
```

`extract-page.js` 内部按 URL 分派到 6 个适配器：

| 适配器 | 主选择器 | 兜底 |
| --- | --- | --- |
| `wechat` | `#js_content` + `#activity-name` / `#js_name` / `#publish_time` | Readability |
| `zhihu` | `.Post-RichTextContainer .RichText` / `.RichContent-inner` | Readability |
| `xiaohongshu` | `#detail-desc` + 轮播图集合 | — |
| `ima` | 拦截到的 JSON 中的文件树 + DOM 目录节点 | Readability |
| `news` | 20+ 常见正文容器选择器 | Readability |
| `generic` | 用户自定义规则 → Readability → 通用容器选择器 | — |

### 4.2 导出流水线

```
exportResult(result, options)
    │
    ├─ 1. localizeImages()   下载全部图片
    │       ├─ Electron net 通道（携带 Cookie，可下载需登录的图）
    │       ├─ 失败自动回退 Node https/http 直连
    │       ├─ 转 base64 内嵌（供 PDF/Word/HTML）
    │       └─ 落盘到 <文件名>.assets/（供 Markdown 相对引用）
    ├─ 2. buildDocumentHtml()  元信息头 + 正文 + 阅读器样式 + 页脚
    ├─ 3. htmlToPdf()          屏幕外窗口 loadFile → printToPDF
    ├─ 4. htmlToMarkdown()     turndown(GFM) + 列表空行规范化
    ├─ 5. htmlToDocx()         html-to-docx（失败降级 .doc）
    └─ 6. 写历史记录 + 触发右下角提醒
```

### 4.3 任务调度

- **任务间并行**：由 `concurrency` 控制（默认 3）。
- **任务内串行**：一个任务的多条链接顺序处理，避免单任务占满并发槽。
- **取消**：`flags.canceled` 标记 + 从 pending 队列移除；抓取中通过 `withTimeout` 的清理回调销毁窗口。
- **重试**：`task.retry()` 只重置 failed/canceled 的子项。

### 4.4 资源嗅探（`services/sniffer.js`）

```
点击「嗅探」→ sniffer.start(webContentsId)
    ├─ wc.debugger.attach('1.3') + Network.enable
    ├─ 监听 Network.responseReceived → classify(type, url, mime, headers)
    ├─ scanDom()     executeJavaScript 扫描已加载 DOM 的 img / a / link / object
    └─ 命中 → emit('update') → 主进程节流 260ms → IPC 推给渲染进程增量渲染
```

**过滤策略（两层，确保绝不混入音视频）**：

1. **硬排除**：`type === 'Media'`、MIME 以 `video/` / `audio/` 开头、URL 命中 `MEDIA_EXT` 正则
2. **白名单归类**：只收 `image` / `doc` / `zip` / `file` 四类，且排除 html/css/js/字体等网页自身资源
3. **附加过滤**：`content-length < 1536` 的图片视为统计像素丢弃

**并发与清理**：下载并发 4；页面 `destroyed` 时自动 detach 调试器，避免句柄泄漏。停止嗅探只关闭监听、**保留已收集结果**。

**与解析功能的隔离**：`parseWebviewPage()` 用的是 `runExtractionRetry()`（不启用 CDP），因此嗅探占用 debugger 时依然可以正常「解析此页」。

### 4.5 内置浏览器导航

| 场景 | 处理 |
| --- | --- |
| 地址栏输入 | `browser:resolveUrl` → `looksLikeUrl()` 判定：是网址补协议，否则 `buildSearchUrl()` 走搜索引擎 |
| 页内普通链接 | webview 自身导航（默认行为） |
| `target="_blank"` / `window.open` | `setWindowOpenHandler` 拦截 → 通知渲染进程 `browser:open-url` → 在当前 webview 内打开 |
| 非 http(s) 协议 | `will-navigate` 中阻止 |
| 隐藏抓取窗口内的弹窗 | 一律 `deny`，防止隐藏窗口泄漏 |

### 4.6 知识库深抓（递归展开目录树）

对应 `extract-page.js` 顶部的 `window.__TND_TREE__` 与 `extractor.js` 的 `deepCapture()`。

```
deepCapture(target, base, options)
    ├─ ① window.__TND_TREE__.expand(12)      多轮展开，直到节点数不再增长
    ├─ ② 重新 extract 一次，拿到完整目录树（含深层文件 + 层级路径）
    ├─ ③ 遍历叶子文件：
    │      window.__TND_TREE__.click(path, title)  →  sleep  →  extract  →  hash 去重
    └─ ④ 产出 sections[{title, path, html, text}]，导出时保留层级
```

**目录树识别的三条启发式规则**：

1. **树根定位**：在一组「像目录容器」的选择器里找，并且要求容器位于页面**左侧 55% 区域内**——这条约束能有效排除正文列表，避免在普通文章页上误判。
2. **层级推导**：优先数 DOM 嵌套层数；遇到「扁平 DOM + 缩进表示层级」的树，退化到按 `padding-left + margin-left` 估算，并且**必须减去容器内最小缩进作为基准**。
3. **标题提取**：优先取 `:scope > [class*=title]` 等标题子元素；取不到时**只拼接直接文本节点**（`childNodes` 里 nodeType===3 的），绝不能把整棵子树的文字算进来。

**展开循环为什么必须多轮**：展开上层文件夹会带出下层的文件夹，一次性扫描只能拿到第一层。每轮重新扫描 → 点击所有仍处于折叠态的文件夹 → 比对节点数，不增长即收敛。

### 4.7 文件直下通道（`services/downloader.js`）

当链接本身指向文件（`.zip/.pdf/.docx/...`）时，走这条通道而不是网页解析。

- **流式写盘**：边收边写，不把整个文件读进内存，可安全处理几百 MB 的压缩包
- **双通道**：先 Electron `net`（能带 Cookie），失败回退 Node `https`，与图片下载同源的策略
- **文件名**：优先解析 `content-disposition`（含 `filename*=UTF-8''` 形式），退化到 URL 末段，中文名正确保留
- **落盘位置**：`<导出目录>\直接下载\`，同名自动加序号不覆盖

### 4.8 IMA 知识库导出（独立功能区，`services/imaApi.js`）

> 对齐开源项目 [wandao](https://github.com/tllovesxs/wandao) 的实现：IMA 官方提供 OpenAPI，走接口比抓 DOM 更快更稳，输出按目录结构落盘。

**独立功能区**：左侧导航「IMA 知识库」对应独立页面 `pages/ima.js` 与主进程 `imaApi`，与「链接导出」在入口、界面、流程上完全隔离（`taskQueue` 不再参与 IMA 导出）。流程：保存凭据 → `listKnowledgeBases` → 选择知识库 → `scanToc` 读取目录树 → 勾选文档 → `exportToTree` 导出；`exportToTree` 通过 `ima:progress` 事件推送进度，页面内实时展示（不进任务中心）。

**认证**：`POST https://ima.qq.com/openapi/...`，请求头 `ima-openapi-clientid` + `ima-openapi-apikey`。凭据到 `https://ima.qq.com/agent-interface` 登录后申请（与网页登录 Cookie 是两套体系，无法自动读取）。

**核心接口**（均为 `POST` + JSON）：

| 用途 | 端点 | 关键请求/响应字段 |
| --- | --- | --- |
| 知识库列表 | `/wiki/v1/search_knowledge_base` | `{cursor,limit,query}` → `knowledge_base_list[]` |
| 目录遍历 | `/wiki/v1/get_knowledge_list` | `{knowledge_base_id,folder_id,cursor,limit}` → `knowledge_list[]` |
| 文档元信息 | `/wiki/v1/get_media_info` | `{media_id}` → `media_type` / `note_id` / `url_info` |
| 笔记正文 | `/note/v1/get_doc_content` | `{note_id,target_content_format:1}` → `content`（Markdown） |

**输出格式（与 wandao 一致）**：

```
输出根目录/
  知识库名/                    ← autoOutputFolder 默认开启；关闭则直接落在根目录
    文件夹A/子文件夹/
      笔记标题.md              ← 笔记正文（以 # 标题 开头）
      笔记标题_assets/
        image-001.png          ← 正文图片本地化
      附件标题.pdf             ← 附件原样保存（同名加 _2）
```

- 文件名清理 `sanitizeFilename`：非法字符 → `_`，空白折叠，去首尾 ` .`，截断 180 字
- 同名唯一化 `uniquePath`：`名.ext → 名_2.ext → 名_3.ext`
- 扩展名推断 `extensionForDownload`：标题后缀 → `content-type` → `.bin`
- 图片本地化 `localizeMdImages`：正则取 `![..](url)`，逐张下载为 `image-001.ext`，正文改写为相对引用

**落盘细节**（`saveNoteEntry` / `saveMediaEntry`）：`media_type === 11` 走 note 接口（`get_doc_content` 先试 `format:1`，失败降级 `0`）；其余取 `url_info.url` 与其 `headers` 直链下载，先写临时目录 `.tnd-ima-tmp` 再改名，避免半成品。`main.js` 暴露 `ima:listKnowledgeBases` / `ima:scanToc` / `ima:exportTree` 三个 IPC。

**健壮性设计**：
- 字段名**宽松兜底**：`pick(obj, ['a','b','c'])` 支持嵌套路径（`'data.url'`），应对官方接口字段命名变化
- 目录列表提取 `findNodeArray` 从响应任意深度找「最像列表」的数组
- 自检：`TND_IMA_OPENAPI_BASE` 环境变量可覆盖 BASE 指向本地 mock 服务（`scripts/test-ima.js`）

### 4.9 任务持久化

`TaskQueue` 持有 `data/tasks.json`：

- **写入**：`emitUpdate()` 里触发，防抖 800ms 合并；退出前 `before-quit` 强制 `flush()`
- **恢复**：启动时读取，把 `running`/`queued` 的任务标记为 `interrupted`、其未完成条目标记为 `failed` 并注明「应用退出时任务被中断」，避免列表里永远卡着「进行中」
- **上限**：最多保留 300 条

界面层按「今天 / 昨天 / N 天前 / 具体日期」分组呈现，顺序即时间倒序。

## 五、踩过的坑（重要，勿回退）

这一节记录的每个问题都曾导致功能完全不可用，改动相关代码前请先读。

### 5.1 `show: false` 的窗口会让注入脚本永久挂起

**现象**：解析任务卡死，105 秒后被硬超时掐断，日志无任何报错。
**原因**：Chromium 把不可见窗口视为后台页面，**节流甚至冻结定时器**。注入脚本第一个 `await sleep()` 的 `setTimeout` 永不触发。
**解法**：窗口改为「屏幕外 + 完全透明 + 不抢焦点」：

```js
new BrowserWindow({
  show: true, x: -24000, y: -24000,
  skipTaskbar: true, focusable: false, frame: false,
  webPreferences: { backgroundThrottling: false }
})
win.setOpacity(0)
```

### 5.2 `innerText` 会把提取从 3 秒拖到 100 秒

**现象**：抓 IT之家首页时脚本执行超过 100 秒。
**原因**：`innerText` 触发**强制同步重排**（reflow）。在「判断元素有没有内容」这类高频判断中反复调用，代价呈指数级放大。
**解法**：凡长度判断一律用 `textContent`（`leanText` / `leanLen`）；`innerText` 只在最终生成正文时调用一次。

### 5.3 无限滚动页面导致自动滚动死循环

**现象**：脚本永不返回。
**原因**：`for (let y = 0; y < document.documentElement.scrollHeight; ...)` —— 在循环条件里重新读取滚动高度，而滚动本身会让高度持续增长。
**解法**：进入循环前**快照高度**，并加最大步数上限。

### 5.4 HTML 实体未解码导致图片全部下载失败

**现象**：公众号导出后 7 张图全部失败，警告「已保留原始链接」。
**原因**：`innerHTML` 序列化会把 `&` 转义成 `&amp;`，主进程用正则从 HTML 里取出的 `src` 带着 `&amp;`，请求到了错误 URL。
**解法**：收集与分析时统一 `decodeEntities()`；替换时改用**回调式 `String.replace(regex, fn)`**，在 `<img>` 标签内就地替换，避免全局字符串正则误伤。

### 5.5 `net::ERR_BLOCKED_BY_CLIENT`（Electron 网络层被拦截）

**现象**：`mmbiz.qpic.cn` 的图片通过 Electron `net.request` 一律被客户端阻止。
**解法**：`requestBuffer()` 改为双通道 —— 先 Electron net（可带 Cookie），失败自动回退 Node `https`/`http`。两条通道互补，覆盖公开图与需登录图。

### 5.6 CDP `sendCommand` 永久 pending

**现象**：`debugger.attach()` 后 `Page.enable` 永不 resolve，抓取启动即卡死。
**解法**：attach 前先 `loadURL('about:blank')` 预热 target；所有 CDP 命令包在 `Promise.race` 中限时 6 秒，超时则 detach 并**降级为纯 DOM 提取**（功能不受影响，只是拿不到 SPA 的接口数据）。

### 5.7 SPA 首帧后的路由跳转

**现象**：知乎报 `WebFrame was removed before script could run`。
**解法**：加载完成后再等 700ms 静默期；`runExtractionRetry()` 对 `WebFrame was removed` 等瞬时错误自动重试 3 次。

### 5.8 测试脚本必须阻止 `window-all-closed`

在纯脚本环境下（非完整应用），抓取窗口销毁后会触发 Electron 默认的「窗口全关即退出」，导致后续导出代码被截断。测试脚本需显式注册空的 `window-all-closed` 监听。

### 5.9 `ELECTRON_RUN_AS_NODE=1` 会让 Electron 以 Node 模式启动

某些终端环境会预设该变量，此时 `electron.exe .` 会以纯 Node 运行 `main.js`，报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`（`app` 为 undefined）。启动前需 `unset ELECTRON_RUN_AS_NODE`。

### 5.10 内置浏览器点链接弹出原生窗口

**现象**：在内置浏览器里点搜索结果，弹出一个带「文件 编辑 视图 帮助」菜单栏的独立窗口 —— 那是 Electron 自动创建的 BrowserWindow，与应用的 UI 完全割裂。
**原因**：`target="_blank"` 与 `window.open()` 默认会新建窗口。webview 元素上的 `new-window` 事件在较新 Electron 中已不可靠。
**解法**：在主进程用 `app.on('web-contents-created')` 捕获所有 webContents，对 `type === 'webview'` 的执行 `setWindowOpenHandler`，返回 `{ action: 'deny' }` 并把 URL 通过 IPC 交回渲染进程，在当前 webview 内打开。渲染层的 `new-window` 监听保留作为兜底。

### 5.11 CDP debugger 的占用冲突

嗅探器需要 `debugger.attach`，而抓取引擎的 `enableNetworkCapture` 也需要。二者若同时 attach 同一 webContents 会抛错。
**约定**：内置浏览器的「解析此页」走 `runExtractionRetry`（不 attach），嗅探走 `Network.enable`。新增功能时请遵守这条分工，不要两边都 attach。

### 5.12 嗅探漏抓页面上的文档链接（两个 bug 叠加）

**现象**：页面里明明有 PDF / Word / Excel 链接，嗅探一条都抓不到。
**原因有两个，缺一不可**：

1. `scanDom()` 用的是 `a.getAttribute('href')`，拿到的是 `/files/x.pdf` 这类**相对路径**，
   随后又被 `/^https?:/` 的预过滤直接丢掉。必须改用 **`a.href`**（DOM 属性会自动补全为绝对地址）。
2. `classify()` 里有一句 `if (type === 'Document') return null`。而**点击一个 PDF 链接时，
   CDP 上报的资源类型恰恰就是 `Document`** —— 用户真正想要的文档被这条规则全部拦掉了。

**解法**：`a.href` 绝对化；去掉对 `Document` 的一刀切，改为「有明确文件扩展名或文档 MIME 就收录，
再用 `WEB_ASSET_EXT` + `text/html` 把真正的网页排除掉」。分类顺序也调整为**扩展名优先、MIME 兜底**，
否则 `application/octet-stream`（大量下载站都返回这个）会把 `.exe` 误判成压缩包。

### 5.13 树操作函数定义在闭包内，外部拿不到

**现象**：`window.__TND_TREE_LIST__` 恒为 `undefined`，深抓永远无法展开目录。
**原因**：这些函数最初写在 `window.__TND_EXTRACT__ = async function(){...}` 的**函数体内**，
只有解析跑过一次才会注册。任何在解析之前访问它们的代码都会失败。
**解法**：把目录树 API 提取为**顶层独立 IIFE**（`window.__TND_TREE__`），
`__TND_EXTRACT__` 内部通过 `treeApi()` 安全包装访问。注册与调用彻底解耦。

### 5.14 深抓触发门槛设得比「未展开时的节点数」还高

**现象**：目录树能被识别，但深抓一次都不触发，表现就是「抓不到更深一层的内容」。
**原因**：判定条件写的是 `items.length >= 3`。而知识库**未展开时**往往只有两三个顶层文件夹，
直接被挡在门外。
**解法**：改用两个信号，满足其一即触发 ——
① 存在 `aria-expanded !== 'true'` 的文件夹（最可靠，展开后条目必然增长）；
② 条目已 ≥5 且其中至少 3 个是文件（应对进入时就已全部展开的知识库）。

### 5.15 缩进基准没减，最外层节点被算成第 1 层

**现象**：层级路径前面多出一段空层级（`/产品资料` 而不是 `产品资料`），导出结构错位。
**原因**：退化到缩进推算时，直接拿 `paddingLeft / 16` 当层级。而最外层节点自身也有普通内边距（10px），
`round(10/16) = 1`。
**解法**：先扫描容器内所有节点，取**最小缩进作为基准**，层级 = `round((自身缩进 - 基准) / 16)`。

### 5.16 展开循环过早 break

**现象**：文件夹点了一轮就不再点，深层目录永远展不开。
**原因**：循环里用 `if (items.length === prevCount) break;` 判断收敛，但下一轮的节点数还没算出来，
用上一轮的结果做比较会在第一轮之后立刻退出。
**解法**：把收敛判断放在**每轮重新扫描之后**，并给节点加 `aria-expanded=true` 标记，
避免不通过 aria 表达状态的树被反复点击、来回折叠导致计数永远不变。
（实际实现里在 `expand()` 顶部保留一份 `trace` 轨迹，出问题时能一眼看出每轮扫到多少节点。）

### 5.17 图片本地化异常会让整个多文档结构静默丢失

**现象**：知识库导出后只剩第一页内容，或者多文档合并退化成单文档，且没有任何报错。
**原因**：早期实现是「把多篇文档拼成一个 HTML → 统一本地化图片 → 再用正则 `split(/<div data-tnd-part="\d+">/)`
拆回各章节」。只要本地化环节抛一次异常（例如拿不到 Electron session），就会走 catch 分支，
`localized.html` 保持为初始值 —— 拆不出任何章节，`sections` 变成空数组，多文档结构无声消失。
**解法**：改为**逐篇独立本地化**（`Promise.all` 并发），任何一篇失败只影响那一篇并写入 `warnings`，
其余文档与整体结构完好。

### 5.18 父节点标题把整棵子树的文字都吞了

**现象**：目录树里每个节点的标题都是「产品资料 产品需求 需求文档v1 …」这种拼接文本。
**原因**：用 `el.textContent` 取标题，而 `textContent` 包含所有后代节点的文字。
**解法**：优先取 `:scope > [class*=title]` 这类明确的标题子元素；
取不到时**只拼接直接子文本节点**（`childNodes` 中 `nodeType === 3` 的）。

### 5.19 `capturePage` 与窗口透明度

窗口设为 `setOpacity(0)` 或位于屏幕外时，`webContents.capturePage()` 会报
`Current display surface not available for capture`。自动化截图脚本需把窗口放到屏幕内且不透明。

### 5.20 `pick(obj, keys, undefined)` 会把「未命中」变成空串

**现象**：IMA 目录里所有文档节点都被当成文件夹，整库只抓到一个文件。
**原因**：取值辅助函数 `pick(o, keys, fallback)` 末尾写成 `return fallback === undefined ? '' : fallback`。调用方传 `undefined` 想要一个「未命中哨兵」，却拿到 `''`，于是 `hasListKey !== undefined` 恒真 → 所有节点命中文件夹分支。
**解法**：改用 `Object.prototype.hasOwnProperty.call(o, k)` 判断字段是否存在，不依赖哨兵值；`pick` 同时支持 `'a.b.c'` 嵌套路径（原实现 `o['data.url']` 永远取不到）。

### 5.21 Node 兜底 HTTP 通道原本只支持 GET

**现象**：IMA 接口（全为 POST）在 Electron 网络层被拦时，Node 回退通道拿不到数据。
**原因**：`http.js` 的 `nodeRequest` 用 `mod.get(...)`，无法发送请求体。
**解法**：改用 `mod.request({ method, ... })` 并补 `req.write(o.body)`。图片下载走 GET 不受影响，POST 接口现在也能回退。

### 5.22 附件下载请求不带 openapi 凭据头

**现象**：IMA 开放接口通道自测时，附件下载失败（mock 返回 401）。
**原因**：文件直链是 COS 地址，请求不携带 `ima-openapi-*` 头；若 mock 服务把所有请求都做凭据校验，文件下载会被拒。这是**测试脚本的坑**，真实 COS 直链本就无需该头。
**解法**：mock 服务的文件路由放在凭据校验之前；同时提醒——排查 IMA 附件下载问题时，先确认直链本身可匿名访问。

## 七、扩展开发

### 7.1 新增一个平台适配器

1. 在 `src/shared/constants.js` 的 `PLATFORM_DEFS` 中加一条（`match` 正则必须在 `generic` 之前）：

```js
{
  key: 'bilibili',
  name: 'B站专栏',
  match: [/bilibili\.com\/read/i],
  accent: '#fb7299',
  needsLogin: false,
  scrollRounds: 3
}
```

2. 在 `src/main/inject/extract-page.js` 的 `EXTRACTORS` 中加同名方法，返回：

```js
{
  contentEl,        // 必填：已 normalizeImages + sanitize 的正文元素
  title, author, publishTime, cover,
  directory,        // 可选：目录数组 → 触发深抓
  usedReadability   // 可选
}
```

3. 无需改动主进程，路由会自动生效（`EXTRACTORS[platform]`）。

### 7.2 自动滚动 / 展开按钮

在 `PLATFORM_DEFS` 中通过 `scrollRounds`、`expandAll` 控制；`extract-page.js` 的 `autoScroll()` 与 `expandAll()` 会自动执行。滚动与展开都有硬上限，**千万不要写成与页面高度相关的循环**（见 5.3）。

### 7.3 自定义解析规则（用户侧，无需改代码）

由 `plugins.matchRule(url)` 匹配后作为 `options.rule` 注入到页面，`EXTRACTORS.generic()` 会优先使用它。


## 九、已知限制

| 限制 | 说明 | 可能的改进方向 |
| --- | --- | --- |
| 仅 Windows x64 | 未提供 macOS / Linux 构建 | 增加 `mac` / `linux` target |
| 未做代码签名 | 安装时会出现 SmartScreen 提示 | 购买 EV 代码签名证书 |
| Chrome 扩展兼容性 | Electron 仅支持部分扩展 API（MV2 为主） | 随 Electron 升级持续跟进 |
| 视频/音频不下载 | 只保留 `<video>` 播放器占位 | 增加媒体流录制能力 |
| PDF 无页眉页脚页码 | `displayHeaderFooter: false` | 提供开关与模板配置 |
| 深抓依赖 DOM 目录结构 | IMA 改版后可能需要同步调整选择器 | 接口数据捕获（CDP）成功后优先走接口 |
| 不做增量去重 | 同一链接重复导出会生成重复文件 | 按 URL 哈希跳过或覆盖 |

## 十、安全与合规

- 渲染进程启用 `contextIsolation: true` + `nodeIntegration: false`，所有能力经 `preload.js` 的 `contextBridge` 白名单暴露。
- 渲染层加载了 CSP，限制脚本来源为 `self`。
- 抓取窗口 `nodeIntegration: false`、`webSecurity: true`，目标网页无法访问 Node API。
- 扩展加载仅限用户主动选择、且仅加载到抓取会话，不影响主界面安全边界。
- 应用仅面向**个人学习与资料归档**场景，不对绕过付费墙、破解访问限制提供任何能力。
